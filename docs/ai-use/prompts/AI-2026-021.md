## Exact human-authored prompt

Apache Pulsar C++ client — first choice to test. Still very close to libzmq’s domain: messaging, pub/sub, producers/consumers, queues, distributed communication. It is an official Apache C++17 client rather than the broker/runtime itself, so more of the low-level transport machinery may sit behind narrower interfaces. This gives it a better chance of >80% than libzmq while preserving the messaging story.
redis-plus-plus — strong candidate. C++ Redis client with connection pooling, pub/sub, pipelines, transactions, clusters, Sentinel, async APIs, and coroutines. Importantly, it delegates its actual Redis protocol/socket base to hiredis; that could give you exactly the architecture you want: lots of C++ logic around a concentrated external boundary.
ClickHouse C++ client — strong candidate. C++17 infrastructure client implementing ClickHouse’s native protocol, queries, block encoding/decoding, TLS and compression. It is relatively self-contained and its Client is explicitly not internally thread-safe, which may mean less cross-cutting concurrency machinery than libzmq.
Prometheus-cpp — likely very migratable, but less similar to libzmq. Production observability infrastructure with a metrics model, registry, HTTP exposition, and push/pull collection. This adds a genuinely different infrastructure workload and likely has more ordinary data/control logic than a network runtime.
libpqxx — potentially very clean >80% case. It is the official C++ PostgreSQL client API and deliberately builds on top of the C libpq API. That creates a natural external boundary where low-level operations can remain, while C++ transaction/query/result logic could potentially migrate. It is less messaging-oriented, though.
OpenTelemetry C++ — worth screening, but larger. It is established observability infrastructure with stable traces, metrics, and logs and supports modern C++. I’d specifically audit the SDK/core rather than immediately taking every exporter, because exporters reintroduce gRPC/HTTP/runtime boundaries.
